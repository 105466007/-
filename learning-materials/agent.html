核心概念

一句话定义：Agent（智能体）是一个以大语言模型为"大脑"，能够感知环境、自主规划、调用工具、根据反馈迭代，从而完成给定目标的系统。 （Anthropic 的提法：Agentic systems = workflow + agent；本页讨论的是自主性更高的后者。）
💡 类比：普通聊天机器人像"电话客服"——你问一句它答一句，说完就结束；Agent 更像"实习生"——你给它一个目标，它自己查资料、动手操作、检查结果、发现问题再返工，直到把事情办完。

关键词

LLM 大脑工具调用 Tool Use自主规划反馈循环目标导向人机协作

机制原理

一个典型的 LLM Agent 运行在四个环节的循环里：

  1. 感知（Perceive）：接收任务目标和环境信息——用户指令、文件内容、上一步工具的返回结果，全部进入模型的上下文。
  2. 思考 / 规划（Reason & Plan）：LLM 根据上下文决定："下一步该做什么？是直接回答，还是调用某个工具？" 这一步常见的模式叫 ReAct（Reason + Act），即"先想再做"。
  3. 行动（Act）：执行决策。如果是工具调用，就产生一段结构化的调用请求（如搜索、读写文件、执行代码），系统代为执行后把结果交回。
  4. 观察（Observe）：把行动结果拼回上下文，LLM 判断：目标达成了吗？没有的话，问题出在哪，下一步怎么调整？回到 ①。
✅ 为什么需要循环？单次问答无法处理"结果不可预期"的任务。循环让 Agent 具备了纠错能力——这正是它与"一次性生成"工作流（workflow）的核心差别。

应用场景：客服工单自动处理

某软件公司的技术支持团队用 Agent 处理工单，目标："解决用户工单 #4821：同步失败"。

循环轮次Agent 做了什么体现的能力
第 1 轮读取工单，调用「知识库检索」工具 → 未找到匹配方案工具调用
第 2 轮调用「查询用户日志」工具 → 发现是 token 过期导致 401根据观察调整假设
第 3 轮判断超出权限，调用「转人工」并附上诊断摘要知道边界、求助而非硬撑

关键在于："先查知识库、查不到再查日志、超出权限就转人工"这些决策没有写死在代码里，而是 Agent 在循环中根据观察自主做出的。

常见误区与辨析

误区正确理解
Agent = 会聊天的机器人 区别在于"能否行动"。聊天机器人只输出文字；Agent 能调用工具改变外部世界（读写文件、发请求），并根据结果继续行动。
Agent 完全自主，不需要人类 自主性 ≠ 免监督。生产级 Agent 通常设有人工审批点（如上例的"转人工"）、权限边界和执行上限。自主性指的是"中间步骤不需人逐步指挥"，而非"结果不需人负责"。
用了工具的 AI 系统就是 Agent 要看控制流在谁手里。如果由代码写死"先调 A 再调 B"（workflow），那是流程编排；由 LLM 根据观察动态决定下一步调用什么，才更接近 Agent。

自测题

Q1：用一句话说明 Agent 与普通聊天机器人的本质区别。

参考答案：Agent 以 LLM 为决策核心，能自主调用工具、根据环境反馈迭代行动直至完成目标；聊天机器人只能进行单轮或多轮的文字应答，无法对外部世界采取行动。

答错说明：若只答"更智能"，说明还没有抓住"行动 + 反馈循环"这两个关键词，回到「机制原理」。

Q2：画出 Agent 的基本循环，并说明"观察"这一环为什么不可缺少。

参考答案：感知 → 思考/规划 → 行动 → 观察 →（回到感知）。观察把行动结果带回上下文，使 Agent 能判断任务是否完成、发现意外并纠错；没有观察，行动就是"盲跑"，错了也无法调整。

Q3：某系统按固定顺序"先翻译、再摘要、最后存库"，每步调用一次 LLM。它是 Agent 吗？为什么？

参考答案：不是（它是 LLM workflow / 流水线）。因为每一步的执行顺序由代码写死，LLM 没有根据中间结果自主决定下一步的权限。判断标准是"控制流在代码手里还是在模型手里"。

Q4："给 Agent 越多的自主权越好"——这句话对吗？

参考答案：不对。自主权应与任务风险和可验证性匹配：低风险、易验证的任务可以高自主；高风险（花钱、删数据、对外发送）的任务应设置人工审批。上面的工单例子里"转人工"就是自主地承认边界。
