三个概念如何咬合：Agent · 上下文 · Skill

个人学习资料 · 由 learning-material-generator 生成 · 2026-09-10 · Markdown 版：concept-relationship.md

结论先行

上下文 是工作内存——模型一次推理能看到的全部信息；
Agent 是执行系统——在这块内存上用"感知→思考→行动→观察"的循环干活的系统；
Skill 是知识包——按需注入内存的专家 SOP，平时不占内存，任务匹配时才加载。

全景图

读图：Agent 的每次"思考"从上下文读取信息，"观察"把结果写回上下文；Skill 不参与循环，只在任务匹配时把专业知识注入上下文。

上下文如何影响 Agent 的工作

  1. 决定"知道什么"：目标、环境、工具结果全在上下文里——缺信息，"思考"就是无米之炊。
  2. 决定"记得什么"：多轮循环靠历史写回上下文；窗口有限，长任务必须做摘要压缩与外置笔记。
  3. 决定"像谁"：系统提示框定角色与边界（高风险需人工确认等），直接约束 Agent 的自主范围。

Skill 如何补足上下文

没有 Skill 时，上下文只有两个来源：写死的系统提示、临时的对话内容。Skill 提供第三条路——按需注入的专家知识：

方式注入时机适合内容代价
系统提示每次请求角色与硬规则常驻占 token
对话描述当次对话临时需求重复劳动，易遗漏
Skill任务匹配时可复用的流程与知识平时近零，触发时精准

一个容易忽视的连接点

Skill 的触发机制本身依赖上下文质量：description 要与"用户此刻的说法"在语义上对得上才会被加载。所以"上下文工程"不只是塞资料——让正确的知识在正确的时机"被看见"，本身就是一项核心能力。同理，Agent 循环里每轮观察怎么写回上下文（全文 or 摘要），直接决定下一轮决策的质量。
